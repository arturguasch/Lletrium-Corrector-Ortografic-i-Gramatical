`README_lexique.txt` and `README_fr.txt` are retained verbatim as source attribution/provenance records. `french-pos-dict-0.7.pom` is retained as the artifact's license declaration evidence. This map is intentionally conservative: LanguageTool's module POM says its resources can have licenses different from the module's LGPL-2.1 license. A hash, an LGPL-licensed adapter, or LanguageTool provenance alone does not establish permission to redistribute a data resource.

Project attribution convention: where no individual author is identified, use **“Authorship pending identification; resource sourced from the pinned LanguageTool snapshot”**. This records provenance/authorship only; it does not grant redistribution rights or clear any unresolved resource below.

## License search completed 2026-11-05

The local checkout, each candidate runtime loader, generated source manifests, French resource READMEs, module/Core POMs, and LanguageTool third-party license directory were searched. The exact upstream headers/comments for `multiwords.txt`, `hyphenated_words.txt`, `spelling_global.txt`, `compounds.txt`, `replace.txt`, and `replace_custom.txt` describe their data or format but grant no license. The root POM says LGPL refers to source code and resources may have different licenses. Official LanguageTool documentation confirms that `segment.srx` is the rules file used for sentence segmentation; it does not state a separate license for the rules. The `segment-license.txt` file names Jarek Lipski's MIT-licensed Java `segment` library, so it must not be applied to SRX data by proximity. Numbertext's upstream README positively identifies the Soros data dual license and French Belgian/Swiss attribution, but the local `fr.sor` lineage is not byte/version-pinned.

### Release gate from this search

- **Data with identified terms:** the `french-pos-dict:0.7` files (CC BY-SA 4.0) and the mapped Dicollecte files (MPL 2.0), subject to shipping their notices and documenting transformations.
- **Active sources still requiring resolution (9):** `fr.sor` lineage, `multiwords.txt`, `hyphenated_words.txt`, `spelling_global.txt`, `compounds.txt`, `replace.txt`, `replace_custom.txt`, `segment.srx`, and `synonyms.txt`. For `fr.sor`, the license family and attribution are known; its exact upstream lineage is not. The other eight sources lack a resource-specific grant in the evidence found here. Derived aggregate JSON/GZ files are not additional sources; the English POS dependency is tracked separately as shared dependency scope.
- **Project decision:** retain all current French proof resources; do not remove them as part of this phase close. `synonyms.txt` is consumed by the experimental repeated-words rule, so it is retained too. The proof ZIP remains experimental and the French catalog entry stays inactive. Reopen the rights review before publishing/distributing unresolved resources; their presence in a local proof ZIP is not evidence of a redistribution grant.

The next conclusive step for the remaining LanguageTool resources is written confirmation from LanguageTool's maintainers or a clear license/notice in the exact pinned upstream revision. If that cannot be obtained, exclude or replace the affected resource and rerun only the French behavior checks that consume it. This is a documentation of evidence, not legal advice.
