# LanguageTool pattern runtime

Original Catalan grammar, filters, pronoun table and numeric rules: Jaume Ortolà i Font, Daniel Naber and LanguageTool contributors, according to the file. The Soros interpreter derives from the implementation by László Németh, available under LGPL/BSD alternatives; this adaptation uses the LGPL option. Covered LanguageTool code adaptations are distributed under LGPL-2.1-or-later. The audited source snapshots are in `references/languagetool-ca-central/` and `references/languagetool-audit/`; input hashes are in `references/upstream.lock.json`, selected rules in `config/lt-central-rule-selection.json`, and the generated bundle in `src/dictionaries/central/lt-pattern-rules.json`. Adaptations by this project, 2026.

The Valencian-only `CA_WORD_COHERENCY_VALENCIA` behavior and word pairs follow LanguageTool's `WordCoherencyValencianRule`, `AbstractWordCoherencyRule` and `coherency-valencia.txt` (LGPL-2.1-or-later). The implementation is in `src/language-engine.js`; the pair source hash is recorded beside the runtime rule.

The proof-only French `FrenchSuppressMisspelledSuggestionsFilter` adapter follows LanguageTool's `FrenchSuppressMisspelledSuggestionsFilter` and `AbstractSuppressMisspelledSuggestionsFilter` (LGPL-2.1-or-later), by Jaume Ortolà. It uses the local French tokenizer and spellchecker to discard invalid suggestions and suppress a match when configured. It is in `src/lt-pattern-runtime.js`; this does not activate a French profile.

The French `SuggestionsFilter` adapter also follows LanguageTool's `org.languagetool.rules.fr.SuggestionsFilter` (Copyright 2020 Jaume Ortolà; LGPL-2.1-or-later). It removes full-match regular-expression results from suggestions, using Unicode-aware case-insensitive matching, and preserves a rule match even when no suggestion remains. The proof implementation is in `src/lt-pattern-runtime.js` and does not activate a French profile.

The proof-only French `FindSuggestionsFilter` adapter follows LanguageTool's `org.languagetool.rules.fr.FindSuggestionsFilter` (Copyright 2020 Jaume Ortolà) and `AbstractFindSuggestionsFilter` (Copyright 2021 Daniel Naber), LGPL-2.1-or-later. It reuses the local French Morfologik spell-suggestion, POS-tagging and synthesis resources for candidate generation, filtering, casing and suggestion templates. The Java Damerau ordering is approximated with a local Damerau-Levenshtein ordering only for synthesis fallback candidates; exact suggestion parity is not claimed. The adapter is in `src/french-find-suggestions-filter.js`; it does not activate a French profile.

The proof-only French `MakeContractionsFilter` follows LanguageTool's French filter (Copyright 2021 Daniel Naber) and `AbstractMakeContractionsFilter` (LGPL-2.1-or-later). It applies the four French contractions (`de le` → `du`, `à le` → `au`, `de les` → `des`, `à les` → `aux`) to generated suggestions using Unicode-aware word boundaries. The implementation and its focused fixtures are in `src/lt-pattern-runtime.js`; this does not activate a French profile.

The proof-only French `FrenchNumberInWordFilter` follows the French specialization (Copyright 2021 Stefan Viol) and `AbstractNumberInWordFilter` (LGPL-2.1-or-later). It tries zero-to-letter substitution, digit removal, and then local French spelling suggestions, in the same order as upstream. The implementation is in `src/lt-pattern-runtime.js`; it does not activate a French profile.

The proof-only French `AdvancedSynthesizerFilter` follows LanguageTool's French specialization and `AbstractAdvancedSynthesizerFilter` (Copyright 2020 Daniel Naber; LGPL-2.1-or-later). It selects French morphology readings from the local tagger, synthesizes the requested POS form with the local French data, and expands suggestion templates. French-specific ordering and exception behavior remain subject to differential fixtures. The implementation is in `src/lt-pattern-runtime.js`; it does not activate a French profile.


The proof-only French `WordWithDeterminerFilter` adapter follows LanguageTool's `org.languagetool.rules.fr.WordWithDeterminerFilter` (Copyright 2020 Jaume Ortolà; LGPL-2.1-or-later). It synthesizes determiner+noun/adjective agreement forms using local French morphology, preserves XML-provided suggestion priority, and validates generated suggestions against selected local elision/agreement rules without recursively invoking this filter. The implementation is in `src/lt-pattern-runtime.js`; this does not activate a French profile, and broad output parity is pending.

The proof-only French `InterrogativeVerbFilter` follows LanguageTool's French filter (Copyright 2020 Jaume Ortolà; LGPL-2.1-or-later). It selects the target verb POS from the clitic/pronoun morphology, retrieves candidate spellings with the local French speller, and applies the source handling for `peux-je` and the `-é-je` / `-è-je` variants. It is in `src/lt-pattern-runtime.js`; full differential coverage is still required before activation.

The proof-only French `PostponedAdjectiveConcordanceFilter` adapts LanguageTool's `org.languagetool.rules.fr.PostponedAdjectiveConcordanceFilter` (Copyright 2020 Jaume Ortolà i Font; LGPL-2.1-or-later). It follows the source's noun/determiner scan, French gender/number tags, nominal-group boundaries, agreement exceptions and local French synthesizer. It includes a conservative local disambiguation for capitalized determiners whose tagger output also includes a noun reading when followed by a noun. Focused positive fixtures exercise feminine singular, masculine/feminine plural, and neutral-gender cases; general differential parity has not yet been established. The implementation is `src/french-postponed-adjective-filter.js`; it does not activate a French profile. The complete license is in this directory's `COPYING.txt`.

The proof-only French `MultitokenSpellerFilter` adapter reuses the shared LanguageTool-core `MultitokenSpellerFilter` / `MultitokenSpeller` implementation (Copyright 2023 Jaume Ortolà; LGPL-2.1-or-later). The French candidate rules and candidate ranking are adapted in `src/lt-catalan-filters.js`; the imported French multiword data is generated from LanguageTool's `multiwords.txt`, core `spelling_global.txt`, and French `hyphenated_words.txt`. The exact source files and SHA-256 hashes, generated entry count and compressed/uncompressed hashes are recorded in `build/resources/fr/multitoken_words.manifest.json`. This proof implementation is not enabled as a French profile, and its output equivalence has not yet been established.

The proof-only French sentence tokenizer uses the 83 applicable rules from LanguageTool Core's shared `languagetool-core/src/main/resources/org/languagetool/resource/segment.srx` groups `GeneralImportant`, `ByTwoLineBreaks`, `French` and `Default` (source SHA-256 `2166e248ea6bde88e2cc8137cd44aa2d0078c02fe3d78ff28d270387c096cbbe`). The extracted rule data is generated into `build/resources/fr/fr-srx.json`; the browser adapter is in `src/french-sentence-tokenizer.js` and uses the shared Java-compatible regex runtime. This SRX-derived behavior is proof-only, stays in the extension package rather than a remote language pack, and does not enable French in the UI/worker. It is covered by nine focused sentence-boundary fixtures; broad sentence-segmentation parity remains unclaimed. Preserve the LanguageTool LGPL-2.1-or-later attribution and this notice when redistributing the adapter or generated rules.

The proof-only French whitespace adapters in `src/french-whitespace-rule.js` follow the default behavior of LanguageTool's `org.languagetool.rules.fr.QuestionWhitespaceRule` and shared `org.languagetool.rules.MultipleWhitespaceRule` (Copyright 2005 Daniel Naber; LGPL-2.1-or-later). They handle missing French spacing before `?`, `!`, `;` and `:`, missing spaces around French guillemets, and consecutive Unicode space separators; they retain the upstream exclusions for common URLs, clock times, MAC addresses, compact semicolon-separated data, repeated punctuation and smileys. The punctuation rule accepts regular whitespace as the upstream default does; repeated spaces collapse to the first whitespace character. The stricter NBSP-only `QuestionWhitespaceStrictRule` is not activated. Focused adapter cases are in `analysis/french-adaptation/smoke-whitespace-rule.mjs`; full rule-by-rule Java parity has not been established. This proof adapter does not enable a French profile.

The proof-only French `SimpleReplaceRule` adapter and its 30 source entries follow LanguageTool's `org.languagetool.rules.fr.SimpleReplaceRule` (Copyright 2020 Jaume Ortolà; LGPL-2.1-or-later) and `AbstractSimpleReplaceRule` / `SimpleReplaceDataLoader` (LGPL-2.1-or-later). The data were derived from `languagetool-language-modules/fr/src/main/resources/org/languagetool/rules/fr/replace.txt` and `replace_custom.txt`; source SHA-256 values are pinned in `src/french-simple-replace-rule.js` and `build/resources/fr/fr-simple-replace.json`, which preserves source line numbers and suggestions. The adapter matches the default non-strict case behavior, title/all-uppercase suggestion casing, tagged-token and spellchecker-ignore exclusions, and per-form replacement lookup. It processes one lexical token at a time as upstream does, so multiword table rows remain inert. It does not enable a French profile.

The proof-only French `DoublePunctuationRule` adapter in `src/french-core-punctuation-rule.js` follows LanguageTool Core's `org.languagetool.rules.DoublePunctuationRule` (Copyright 2005 Daniel Naber; LGPL-2.1-or-later). It detects adjacent `..` and `,,`, offers the corresponding replacement choices, and preserves the principal upstream exceptions for ellipses, `?..`/`!..`, and slash/backslash path continuations. Focused fixtures use the actual French tokenizer in `analysis/french-adaptation/smoke-core-punctuation.mjs`; this narrow adapter does not claim full Java parity or enable a French profile.

The proof-only French `CommaWhitespaceRule` adapter in `src/french-comma-whitespace-rule.js` follows the shared LanguageTool Core rule (Copyright 2005 Daniel Naber; LGPL-2.1-or-later), instantiated by the French profile with quote-spacing checks disabled. It covers spacing after `(`, before `)`, around commas, and before a full stop. The full-stop branch preserves upstream domain/TLD, file-extension, digit/ellipsis and `./command` exclusions. Source inspection shows the generic proper-noun helper is called on the current punctuation token in this branch, so no preceding-word POS exception is applied for French. Focused positive/negative and pipeline cases are in `analysis/french-adaptation/smoke-comma-whitespace.mjs`. This adapter remains proof-only and does not enable a French profile or claim complete Java parity.

The proof-only French `UppercaseSentenceStartRule` adapter in `src/french-uppercase-sentence-rule.js` follows LanguageTool Core's `org.languagetool.rules.UppercaseSentenceStartRule` (Copyright 2005 Daniel Naber; LGPL-2.1-or-later). It relies on the pinned French SRX segmenter and local tokenizer, and conservatively checks sentence punctuation, quotes, basic list markers, URLs/emails, mixed-case tokens and selected exceptions. It does not reproduce upstream POS/immunization context or claim full parity. Focused fixtures are part of `analysis/french-adaptation/smoke-candidate.mjs`; this rule remains proof-only and does not activate a French profile.

The proof-only missing-space subset in `src/french-whitespace-rule.js` follows LanguageTool Core's shared `org.languagetool.rules.SentenceWhitespaceRule` (Copyright 2014 Daniel Naber; LGPL-2.1-or-later). It only flags an adjacent `.`, `!` or `?` followed by an uppercase lexical token, and excludes one-letter initials and URL-like contexts. It does not reproduce sentence-boundary behavior for lowercase continuations, all abbreviation/domain cases, or the full Java token context. Focused positive/negative fixtures are in `analysis/french-adaptation/smoke-whitespace-rule.mjs`; it remains proof-only and does not activate a French profile.

The proof-only French repeated-word style adapter in `src/french-repeated-words-rule.js` follows `FrenchRepeatedWordsRule` and the shared `AbstractRepeatedWordsRule` (Copyright 2021 Daniel Naber; LGPL-2.1-or-later). It uses the pinned French POS/synthesis resources for lemma matching and suggestions, honors the upstream distance, sentence-start capitalization and POS constraints where available, and skips entries with chunk constraints because this candidate has no chunk tags. The source `build/resources/fr/synonyms.txt` is included only in the proof ZIP; its resource-level license remains pending review in `analysis/french-adaptation/inventory.json`, so it is not approved for public redistribution. The adapter does not enable a French profile.

The proof-only French compound adapter in `src/french-compounds-rule.js` follows LanguageTool Core's `AbstractCompoundRule` and French `CompoundRule` (Copyright 2006 Daniel Naber; LGPL-2.1-or-later). It converts the pinned `compounds.txt` entries to a compact JSON index and checks local French morphology before offering joined or hyphenated suggestions. The adapter currently covers ordinary 2–5-token entries; it does not claim full parity for LanguageTool's token immunization, all tokenization shapes or the complete Java tagging path. The source data's resource-level license has not been established, so both adapter and data remain proof-only and are not approved for redistribution through `language-packs`.

The proof-only French bracket adapter in `src/french-unpaired-brackets-rule.js` follows LanguageTool Core's `GenericUnpairedBracketsRule` (Copyright 2009 Daniel Naber; LGPL-2.1-or-later), configured by the French profile for `[]`, `()` and `{}`. It preserves UTF-16 token offsets, suppresses the upstream-style list-marker and common smiley cases, and reports unmatched delimiters with the French message. Its stack/mismatch handling is a conservative local adaptation and does not claim complete Java parity.

The proof-only adapter in `src/french-long-sentence-rule.js` adapts LanguageTool Core's `LongSentenceRule` (Copyright 2014 Daniel Naber; LGPL-2.1-or-later), using the French profile's 40-word threshold and French message. It preserves source offsets and the upstream quoted-sentence-ending exception; POS-dependent word classification and every Java tokenization edge case are not claimed equivalent.

The proof-only adapter in `src/french-long-paragraph-rule.js` adapts LanguageTool Core's `LongParagraphRule` (Copyright 2020 Daniel Naber; LGPL-2.1-or-later), using the default French 220-word threshold. It recognizes only explicit blank-line paragraph separators and suppresses manual-line-break paragraphs; editor-provided paragraph boundaries and all Java paragraph-end semantics are not claimed equivalent.

The spelling, multitoken and morphology data derived from `org.softcatala:catalan-pos-dict:3.3` retain the upstream dual GPL-2.0/LGPL-2.1 terms; this distribution selects LGPL-2.1 for those data. The source artifact, files, hashes and license choice are recorded in `references/upstream.lock.json`, the resource manifests and `licenses/THIRD_PARTY_NOTICES.md`. The JavaScript spelling trie is a local implementation using Softcatalà equivalence and replacement data; see `licenses/softcatala/` and `licenses/catalan-dict-tools/`.

All execution is local. The original remote rewrite service is replaced by conservative local rules, without claiming equivalent coverage.
